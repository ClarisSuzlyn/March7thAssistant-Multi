# 多账号支持（March7thAssistant）

在**不改动原 UI 与业务逻辑**的前提下，为原项目加上「账号独立配置 + 多账号轮询 + 图像识别切号」。
所有新增代码都带 `# [MULTI_ACCOUNT]` 标记，方便后续同步上游更新。

## 使用

1. 启动程序 → **设置 → 多账号**（第一个标签页）。
2. 顶部操作栏（**悬浮在「设置」标题右侧**，切到任何账号相关 Tab 都能看到，不随页面滚动）：
   - `+` 新建账号：以当前配置为起点复制出该账号的独立配置；`📋` 复制当前账号（可改名）；`−` 删除当前账号；
   - 下拉框切换账号（切号后原界面各设置页立即变成该账号的配置）；
   - **保存配置**：把当前页面的修改写进该账号的 YAML；
   - 右侧 **启动当前配置 ▾**：启动当前账号配置 / 启动所有账号配置 / 仅保存配置。
   切到「程序 / 云游戏 / 推送 / 杂项 / 关于」等非账号 Tab 时操作栏会自动隐藏，避免遮挡卡片。
3. 「账号配置」卡片：
   - 账号名称 / 渠道服（官服，B服暂未开放）
   - 游戏路径：开关指「全局」= 跟随「程序设置」的全局路径；切到「独立」后可单独选择
   - 登录账号 / 登录密码：手机号或邮箱 + 密码（眼睛按钮可切明文查看），密码用 Windows DPAPI 加密存在本机
   - 自动登录 / 总是重新登录
4. 「任务结束」卡片（每个账号独立）：该账号跑完后的收尾动作
   - 跟随程序设置（默认）：沿用「程序设置 → 任务完成后操作」，可触发关机/休眠/循环等
   - 登出当前账号 / 退出游戏（关闭客户端） / 关闭程序 / 无动作
5. 保存语义：**只有点击「保存配置」（或启动前自动保存）才会写入当前账号的 YAML**；
   切换账号时若检测到未保存修改会先询问；页面不再自动保存，也不会自己重建。

## 配置隔离

- **账号级（私有）**：体力 / 日常 / 货币战争 / 差分宇宙 / 锄大地 / 逐光捡金 这几个 Tab 的键，
  白名单见 `core/account_manager.py` 的 `PRIVATE_KEYS`，切换账号时从该账号 YAML 覆盖到
  `cfg.config`。
- **全局**：程序 / 云游戏 / 推送 / 杂项 / 账号 / 关于，以及热键、通知、自动启动、窗口、更新等
  （白名单之外的键一律按全局处理），始终使用当前运行进程的值，不写进账号 YAML。
- 旧版本档案里误存的全局键会在读取时丢弃，避免串配置。

## 启动入口（GUI → 子进程）

- 「启动当前配置」传的是 `multi_account --account <账号ID>`（只跑当前下拉框选中的账号）；
  「启动所有账号」传 `multi_account`（按账号列表顺序轮询）。
- 这两个字符串经 `app/log_interface.py` 的 `_split_task_command()` 拆成参数列表后启动
  `python main.py multi_account --account <ID>`，`main.py` 的 `--account` 参数会把
  `[账号ID]` 传给 `core/scheduler.run_multi_account(account_ids)`。
- 调度链路固定为：UI 发信号 → `main.py` 收到任务 → `core/scheduler.py` 切号
  （`prepare_account`）→ 切号成功后调用原项目任务（`Daily.start()`），不修改原项目
  `run_main_actions` 的逻辑。

## 切号流程（图像识别 + 模板/OCR 双校验）

模板放在 `assets/images/screen/multi_account/`：

| 目录 | 内容 |
| --- | --- |
| `sra/` | 已验证的登录/登出模板（登录页 miHoYo、登录其他账号、账号密码、账号输入框、同意协议、进入游戏、欢迎界面、ESC 菜单电源/登出等） |
| `qq/` | 从实际截图裁剪的按钮/输入框/勾选框/弹窗（退出登录弹窗、黄色退出、登录其他账号、弹窗确认、黄色登录、账号或密码错误等） |
| `legacy/` | 备用的 1920x1080 模板集（分辨率不一致时自动缩放匹配） |

流程：

```
【每个账号开始前】先看进程：客户端没启动就自动拉起并等窗口出现（期间不截图、不乱按 ESC）；
                  客户端已在运行时只切到前台。

【主循环 prepare_account()：状态驱动，不做 UID 校验（对齐原版 SRA 的「勾了就重登，没勾就开打」）】
  ☆ 勾了「总是重新登录」：进入循环第一件事就是无脑登出当前账号（不管当前是谁），
     重登只做一次；登录进游戏后立即返回——不会再出现「登录→进游戏→又登出」的死循环。
每 1~2 秒识别一次当前界面，按状态决定动作：
  A. 游戏内（主界面图标：手机 / 组队 / 头像）
       - 勾了「总是重新登录」→ 登出重登目标账号（只登出一次）
       - 没勾 → 直接开打（不管当前是哪个账号，行为由用户勾选决定）
  B. 登录页（登入 / 登录其他账号 / 账号密码）→ 填目标账号 → 进入游戏 → 返回
  C. 标题页（开始游戏 / 点击进入）→ 无法确认当前是哪个账号：
       自动登录模式一律先点【登出】→「退出」回登录页（先退后进），再登录目标账号；
       未开启自动登录则直接点开始游戏进入
  D. 加载中/黑屏（未知界面）→ 只等不按：每 2 秒看一眼，连续 10 秒识别不到才按一次 ESC
```

- 状态机识别顺序：确认弹窗 → 登录弹窗(进入游戏/登录其他账号) → 账号密码页 → 验证码页
  → 标题页(开始游戏 / 点击进入，两者都算) → 登入按钮(右侧 mi 登入) → 游戏内(手机/组队/头像)。
  每次识别都会打一条 `log.debug("[多账号] 当前状态识别为：…")`，排查时开 DEBUG 即可看到。
- **不做 UID 识别**：全屏 + 左下角日志悬浮窗会遮挡 `UID:数字`，识别失败会卡死；
  当前账号是否正确完全交给「总是重新登录」勾选项（与用户操作约定一致）。

- 【收尾：回到登录页】只有确实「在游戏内」或「标题页」才执行登出：
  游戏内 → 按 ESC 直到呼出菜单（最多 8 次，边退边判主界面图标）→ 点右下电源图标（含红点变体）
  → 弹窗「是否返回登录页面？」点「确认」→ 回标题页；
  标题页仍有「登出」→ 点登出 → 弹窗「退出并保留登录记录」→ 点「退出」→ 登录页。
  弹窗只等 8 秒；模板与 OCR 全部没命中时按两次 ESC 兜底，并把失败直接返回给
  `prepare_account`（抛 `SwitchError`），不会停在标题页死循环。

- 【登录】（三种入口都会自动处理）
  标题页右侧只有「mi 登入」→ 点登入；
  出现「进入游戏 / 登录其他账号」弹窗 → 点「登录其他账号」；
  验证码页 → 点「账号密码」；
  密码页 → 剪贴板粘贴账号、Tab、粘贴密码 → 勾选「保留登录记录」与「同意协议」→ 点「进入游戏」
    → 同时等待欢迎界面 / 开始游戏 / 点击进入。

- 每个关键按钮先做模板匹配、模板未命中再用 OCR 回收（如「退出」/「登出」/「确认」）；
  「退出」与「登出」靠 OCR 文本区分，模板只用来定位，避免点错。
- 单步失败：同一操作最多重试 3 次（间隔 1.5s），失败则回到上一步；
  仍失败则关闭客户端重启一次，重新走完整流程。
- 登录后检测到「账号或密码错误」：清空输入框重填，最多 3 次；仍失败则记录错误、发通知并跳过该账号。
- 每个账号的切号有总超时（`prepare_account(timeout=120)`）：超时抛 `SwitchError`，按「出错跳过」策略处理。
- 登录成功进入游戏后，仍交给原项目 `game.start()` 完成开始游戏 / 点击进入 / 原生登录处理。
- 每一步都会打印 `[多账号] …` 日志（识别到的界面、点击了哪个按钮、第几次重试）。

### 风控弹窗与分辨率（本轮加固）

- `detect_state()` 顺序识别风险弹窗 → 人工验证网页 → 标题/登录/游戏内；风险弹窗会打 5 行 `=` 提示，
  点击黄色【确定】后跳转的网页靠「浅色底 + 几乎没有深色内容」判定，不依赖 OCR 小字。
- `_wait_login_result()` 等待登录结果期间也会拦截风控弹窗：点【确定】后返回 `False`，交回主循环进入
  `STATE_MANUAL_VERIFY`（不再死等到 120 秒超时）。
- 分辨率在「开跑前 / 每个账号开跑前」各纠正一次：客户端没运行 → 写注册表；已运行但不对 → 10 秒提示、
  3 次机会 → 关闭客户端 → 改分辨率 → 重新启动（重新登录由切号状态机负责）。

## 行为约定

- 切号时：保存旧账号配置 → 生成「默认配置 + 该账号配置 + 当前机器级键」→ 覆盖内存 `cfg.config`
  并写回 `./config.yaml`；**同一账号也会先存盘**，所以「体力/日常」等页面里没点保存的改动
  在点「启动当前账号配置」时不会丢。
- 切号成功后对原项目设置页做**软刷新**（`SettingInterface.refresh_values()`）：按 `cfg` 里的新值
  逐个更新现有卡片的显示（下拉框/开关/滑块），**不销毁、不重建任何控件，也不弹「配置已更新」提示**，
  所以切换账号是瞬时的。
- 启动每个账号前先进入 `prepare_account()` 状态循环（不固定 sleep、不截图等 UID）：
  - 勾了「总是重新登录」→ 循环最开头**无脑登出一次**（不管当前是谁），登录进游戏后立即返回，
    不会出现「登录→进游戏→又登出」的死循环；
  - 没勾「总是重新登录」且当前在游戏内 → **直接开打**；当前账号不对是用户没有勾选导致的，
    按约定由用户自己负责（不再靠 UID 识别防串号）；勾选状态保存在账号库；
  - 标题页（开始游戏 / 点击进入）无法确认当前账号 → 自动登录模式一律先登出回登录页（先退后进），
    再登录目标账号；未开启自动登录则直接点开始游戏进入；
  - 加载中/黑屏（未知界面）只等不按 ESC，连续 10 秒识别不到界面才按一次。
- 轮询顺序：账号 1 跑完 → 执行该账号的「任务结束」收尾（默认登出）→ 账号 2……
  只有**最后一个账号**结束才按其「任务结束」设置收尾（默认仍走原项目「任务完成后操作」）。
- 中间账号不会触发关机等重操作；「关闭程序」在中间账号上会提前结束本轮轮询。
- 出错默认跳过该账号继续下一个（可在账号库选项里关闭）。

## 顶部账号栏（胶囊底座）

- `MultiAccountGroup` 只**构建**顶部操作栏（`self.topBar`），不再把它放进自己的布局；页面里只有「账号配置 / 任务结束」卡片。
- `SettingInterface` 初始化时创建 `QFrame#AccountBarCapsule` 胶囊底座（`self.account_bar_frame`），把 `topBar` 装进去：
  圆角 20px、半透明底（浅色 `rgba(243,243,243,0.85)`，深色 `rgba(50,50,50,0.85)`，随 `qconfig.themeChanged` 刷新），
  绝对定位在「设置」标题右侧（x=160, y=25），宽度由内容 `adjustSize()` 自适应，不占页面布局、不随滚动。
- 切到非账号 Tab（程序 / 云游戏 / 推送 / 杂项 / 关于）时 `_update_account_bar_visibility()` 自动隐藏底座，
  切回账号相关 Tab（多账号 / 体力 / 日常 / 货币战争 / 差分宇宙 / 锄大地 / 逐光捡金 / 账号）再显示。
- 设置页顶部预留空间仍是 `setViewportMargins(0, 140, 0, 5)`（标题 + 胶囊栏 + Tab 行），所以卡片不会压到栏下面。
- 栏内边距 12/6、图标按钮 16px 图标；`+`/复制/`-` 与下拉框之间 15px 呼吸间距；「保存配置」用透明的文字按钮弱化存在感。
- 复制账号：`+` 旁的 `📋` 按钮 → 输入新名称 → `core/account_manager.copy_account()`：账号级设置与该账号 YAML 整体复制一份，
  游戏 UID 不复制（首次登录后由调度器重新绑定）。

## 渠道服 / 启动防护

- 渠道服下拉框有 3 项：**官服**、**B服（暂未开放）**、**国际服（暂未开放）**；选中非官服会弹 `InfoBar` 警告
  「该渠道服暂未适配自动登录，只有官服可正常切号」。
- 「启动当前账号配置 / 启动所有账号配置」前会依次校验：已有任务在启动（防止手抖连点）→ 云游戏模式 → 渠道服 → 脏数据保存 → 应用配置；
  任一不满足直接弹 `InfoBar` 并中止，不会把子进程拉起来。
- 调度器侧同样拦截：非官服账号会被跳过并写日志，云游戏模式整轮拒绝执行。
- 以后要适配 B服，需要在 `core/logout.py` 里按渠道选择模板（`Account-images/1111/sg/bl`、`gb` 的模板可直接放进
  `assets/images/screen/multi_account/sra_bl/`、`sra_gb/` 备用），并让 `detect_state` 支持渠道参数。

## 高级（内存黑匣子 / 更新提醒）

- **内存黑匣子**（默认关闭）：账号库选项 `memory_monitor`；开启后后台守护线程每 10 秒采样一次
  `StarRail.exe` 的内存（RSS），只在任务执行期间（调度器 `arm()`/`disarm()`）判定「进程消失 = 闪退」，
  避免切号/登出关客户端时误报。闪退时把最近 1 小时的内存曲线、峰值和程序日志尾部写到
  `settings/multi_account/crash_logs/crash_<时间>.log`，卡片的「打开黑匣子日志」直接打开该目录。
- **更新提醒**：设置页初始化 1.5 秒后在线程里读 GitHub `releases/latest`，只有远端版本号更大时才弹
  `InfoBar`（「原项目有更新」），**不下载、不安装、不阻塞界面**；网络失败静默忽略。

## 排错

| 现象 | 排查 |
| --- | --- |
| 日志出现「截图失败：没有找到游戏窗口」 | 已修：每个账号开始前先用进程检测客户端状态，没启动会自动拉起并等窗口就绪（不会再「没窗口就截图」） |

## 与上游同步

新增能力全部集中在 `core/`、一个新界面文件和模板目录里，原项目只改了 6 个文件（每次都在 10 行以内，且都带 `# TODO [MULTI_ACCOUNT]` 标记）；
`git merge` 上游后按 `TODO [MULTI_ACCOUNT]` 搜索即可确认补丁点。

## 关于「设置 → 账号」

原项目「账号」页是改注册表的切号方式，本改造**不依赖**它，可保留也可在
`app/setting_interface.py` 里注释掉对应 `addSubInterface` 以隐藏，避免与多账号页混淆。
